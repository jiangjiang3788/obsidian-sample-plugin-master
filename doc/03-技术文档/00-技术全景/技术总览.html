技术总览

本页保留现有技术结构说明，并标记未来技术主线：从松散 Block/View 模型逐步走向 Goal/Cycle/Record 关系模型。

状态：重定位草案 最后更新：2026-05-13 格式：HTML

技术分层

层级目录职责
插件入口src/main.tsObsidian Plugin 生命周期、命令注册、设置加载、组合根。
应用层src/appServiceManager、runtime、usecases、capabilities、feature 注册。
核心层src/core业务服务、类型、工具、AI、主题、数据处理。
功能层src/featuresQuickInput、AI Chat、Timer、Settings 等用户功能。
平台层src/platform封装 Obsidian API，提供 Port 实现。
共享层src/shared共享 UI、hooks、styles、utils、debug。
质量脚本scripts架构 gate、边界检查、构建辅助。

未来技术主线

当前实现中，计划 Block、总结 Block、任务和 Statistics View 更像并列能力，缺少稳定的领域关系。后续技术演进应先补清产品模型，再逐步从松散的 Block/View 组织，走向以 Goal、Cycle、Plan、Task、Record、Review、Feedback 为核心的关系模型。

本批边界：只记录技术方向，不改插件代码，也不在本页展开 Goal/Cycle/Record 的实现细节。

核心原则

  • main.ts 负责组装，不承载复杂业务。
  • core 尽量保持平台无关。
  • platform 是 Obsidian API 的隔离层。
  • features 面向用户功能，不能无限膨胀成全局依赖。
  • scripts/*gate* 用于阻止架构边界被破坏。
  • 新技术方案必须先说明服务的目标闭环环节，再讨论文件和接口。
