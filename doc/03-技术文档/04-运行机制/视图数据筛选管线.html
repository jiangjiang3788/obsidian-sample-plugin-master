视图数据筛选管线

本页定义全局数据筛选的技术分层：Layout 保存全局规则，ViewInstance 保存局部规则，core 提供纯筛选管线，视图只消费处理后的 items。

状态：实施中，特殊视图收口已落地最后更新：2026-05-20格式：HTML生命周期：长期技术事实候选

目标数据流

LayoutRenderer
  -> ViewToolbar
     -> DataFilterPanel
        -> RuleBuilder
        -> layout.globalFilters
  -> ViewContent
     -> useViewData
        -> applyViewQueryPipeline
           -> layout global filters
           -> viewInstance filters
           -> keyword
           -> date / period
           -> sort
     -> ViewContainer / viewModel

状态真源

状态位置生命周期职责不负责
Layout.globalFilterssrc/core/types/schema.ts持久化toolbar 全局数据筛选。不保存单个视图私有筛选。
ViewInstance.filterssrc/core/types/schema.ts持久化某个视图模块自己的局部筛选。不承担整个 layout 的筛选。
keyword运行态 / 视图入参临时搜索关键词。不写回 layout。
selectedThemes / selectedCategories旧 Layout 字段兼容期读取旧数据、转换为规则。不继续扩展新能力。

核心边界

层级可以做不应该做相关文件
core定义 FilterRule、字段读取、操作符、纯筛选管线。不 import Preact、MUI、Obsidian UI。schema.ts、fields.ts、itemFilter.ts、viewQueryPipeline.ts
features/settings/layout组合 layout 渲染、面板、持久化更新。不复制筛选算法。LayoutRenderer.tsx、DataFilterPanel.tsx
features/settings/viewEditors提供规则编辑器。不决定规则保存到哪个状态源。RuleBuilder.tsx
shared/ui/views显示通用 toolbar 和视图容器。不直接依赖 DataStore/useCases，不持久化设置。ViewToolbar.tsx、legacy filter 组件
viewModels做分组、统计、展示模型。不重复执行 layout 级全局筛选。taskExecutionViewModel.ts、timelineViewModel.ts、statisticsViewModel.ts

建议接口草案

export interface ViewQueryInput {
  items: Item[];
  layoutFilters?: FilterRule[];
  viewFilters?: FilterRule[];
  keyword?: string;
  dateRange?: [Date, Date];
  layoutView?: string;
  isOverviewMode?: boolean;
  useFieldGranularity?: boolean;
  sort?: SortRule[];
}

export function applyViewQueryPipeline(input: ViewQueryInput): Item[];

执行顺序原则

  1. 先应用 Layout 全局筛选：代表用户当前看这个 dashboard 的总体条件。
  2. 再应用 ViewInstance 局部筛选：代表某个模块自己的数据源约束。
  3. 再应用 keyword：减少 UI 搜索输入对持久化规则的污染。
  4. 再做日期/period/overview 逻辑：保持当前时间视图行为。
  5. 最后排序：排序不改变筛选集合，只改变展示顺序。

兼容策略

旧字段不在第一阶段从数据模型删除，但 toolbar 不再继续把它们作为新交互入口。layoutFilterAdapter 负责判断当前 layout 是否显式拥有 globalFilters：如果有，即使是空数组也以新版为准；如果没有，则把旧 selectedThemes / selectedCategories 只读转换为规则。用户编辑、清空或点击迁移后，持久化写入 globalFilters 并清空旧字段。

没有 globalFilters 字段 -> selectedThemes / selectedCategories 只读适配
存在 globalFilters 字段 -> globalFilters 是唯一真源
迁移动作              -> globalFilters + 清空 selectedThemes / selectedCategories

特殊视图收口规则

  • 普通视图：统一使用 useViewData → applyViewQueryPipeline，按 layout filters、view filters、keyword、date/period、sort 顺序处理。
  • TaskExecutionView：使用 allItems + applyViewBaseFilters，只应用 layout/view/keyword 基础筛选；open recurring task 不按当前日期裁剪，completed records 再按 doneDate 限制到当前周期。
  • TimelineView：输入 items 已由管线处理，viewModel 只做任务解析、日列构建和汇总，不再二次 filterByRules(module.filters)。
  • StatisticsView：输入 items 已由管线处理；如果 layout filters 中存在明确类别规则，仅用这些类别收窄统计配置展示，不再读取旧 toolbar 分类状态。

测试切面

  • filterByRules：字段读取、tags、themePath、extra、空值和数字比较。
  • applyViewQueryPipeline：layout filters + view filters + keyword + date + sort 的顺序。
  • 兼容测试：旧 selectedThemes / selectedCategories 仍能生效；显式迁移后旧字段清空，空 globalFilters 不回退旧字段。
  • 特殊视图测试：TaskExecution 保留跨日期 open task 且只统计本期 completed records；Timeline 不重复 view filters；Statistics 类别收窄来自 layoutFilters。
