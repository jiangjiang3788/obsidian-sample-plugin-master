字段类型、语义与存储协议

本页定义新字段系统的合同：字段类型负责值结构和输入控件，字段语义负责业务含义，字段存储负责写入位置，字段来源负责解释数据来自哪里。

状态：当前有效最后更新：2026-05-21格式：HTML

核心原则

字段必须拆成四个维度：类型、语义、存储、来源。字段名只用于显示和 Markdown key，不再决定业务含义。

例子：用户可以把主题字段命名为“领域路径”“主题树”“我的分类”，只要 semantic = themePath，系统就知道它是主题路径。

FieldDefinition v2 草案

export interface FieldDefinition {
  id: string;
  key: string;            // Markdown / storage key，可由用户自由命名
  label: string;          // UI 显示名
  type: FieldType;        // 值结构与输入能力
  semantic?: FieldSemantic;
  category: FieldCategory;

  cardinality?: 'single' | 'multi';
  hierarchical?: boolean;
  required?: boolean;
  defaultValue?: unknown;

  storage: FieldStoragePolicy;
  aliases?: string[];     // 只用于读取旧数据，默认不写回

  display?: FieldDisplayPolicy;
  filter?: FieldFilterPolicy;
  search?: FieldSearchPolicy;
  migration?: FieldMigrationPolicy;
}

export interface FieldStoragePolicy {
  scope: 'core' | 'semantic' | 'extra' | 'file' | 'derived' | 'legacy';
  markdownKey?: string;
  writeMode?: 'inline-task-kv' | 'block-kv' | 'frontmatter' | 'virtual';
  readOnly?: boolean;
}

兼容策略

旧字段/旧逻辑新归宿迁移策略
themelegacy 字段；标准语义为 themePath。读取时转成 themePath origin；默认隐藏 theme；不再从 header fallback。
pintusemantic=image 的 legacy alias。读取旧 pintu，写入新 image 字段；UI 不再判断 key。
extra.正文/内容legacy alias，不是真 extra。只在旧编辑回填缺失时兜底；字段选择器默认隐藏。
categoryKeysemantic=categoryPath 或 recordKind 拆分。先保留兼容，再拆 recordKind/categoryPath。
rating + 图片 optionrating 与 image 分离。评分继续用 rating；图片选择走 image 字段。
