字段系统高质量完成线总览

字段系统不再只是表单控件集合，而是记录、输入、解析、视图、筛选、搜索、迁移的统一协议。本页给出总览、不变量和阅读顺序。

状态：当前有效最后更新：2026-05-21格式：HTML

阅读顺序

  1. 字段系统高质量完成线总览：确认目标、边界和不变量。
  2. 字段分类与数据来源模型：回答每个字段的数据从哪里来。
  3. 字段类型、语义与存储协议：建立 FieldDefinition v2。
  4. 解析、渲染、搜索、编辑管线重构方案：收束散落逻辑。
  5. 图片字段与多值层级字段能力设计：把图片、标签、主题、分类做成基础能力。
  6. 实施计划：按阶段落地。
  7. 架构评审 与 测试验收清单：实施前后检查。

当前必须守住的不变量

不变量说明验证方式
header 不参与主题header 只表示 Markdown 所在章节。它不能写入 theme，也不能生成 themePath/rootTheme/leafTheme。静态 grep + DataStore 单测 + snapshot 单测。
主题筛选 = themePathUI 上显示“主题路径”，语义为完整主题路径；theme 仅历史兼容，不作为默认筛选字段。字段注册表检查 + 筛选面板默认项检查。
extra 只收显式未知 KVparser 不再自动生成 extra.正文/内容/任务内容/记录内容/editableText。parser 单测 + 字段选择器 hidden 规则。
字段名不决定语义字段 key/label 可以自由命名；语义由 FieldSemantic 定义。新字段配置测试：把主题字段命名为“领域路径”仍能作为 themePath 工作。
类型不等于语义单选、多选、文本、图片是值结构和输入能力；主题、标签、分类是业务语义。FieldDefinition schema 测试。
