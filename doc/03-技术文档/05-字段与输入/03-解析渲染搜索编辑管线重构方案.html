解析、渲染、搜索、编辑管线重构方案

本页把字段相关的读取、归一、输入、写入、展示、筛选、搜索统一到一条管线，避免修复在一个文件生效、另一个文件又复活旧逻辑。

状态：当前有效最后更新：2026-05-21格式：HTML

为什么要收束管线

当前字段逻辑散落在 parser、DataStore、recordSnapshot、editStateResolver、InputService、OutputPlanner、FieldPill、筛选面板、搜索服务中。任何一处保留旧 fallback，都会把已修复的问题重新带回来。

目标管线

1. 读取阶段
   MarkdownTaskCodec / MarkdownBlockCodec
   - 解析原始 Markdown
   - 识别显式 known field
   - 未知 KV 进入 extra 并记录 origin

2. 归一化阶段
   RecordNormalizer
   - 填充核心字段
   - 计算只读派生字段
   - 禁止 header -> theme

3. 解析阶段
   FieldValueResolver
   - 按 FieldDefinition 读取字段
   - 返回 value + displayValue + origin

4. 输入阶段
   FormDataMapper
   - Record -> FormData
   - FieldDefinition 决定控件和值结构

5. 写入阶段
   FieldValueCodec + OutputPlanner
   - FormData -> Markdown
   - aliases 只读不写
   - legacy fallback 不写回

6. 视图与检索阶段
   ViewFilter / Sort / Search / Retrieval
   - 统一通过 FieldValueResolver
   - 多值字段使用 any/all/contains 语义

模块拆分

模块职责替代旧逻辑
MarkdownTaskCodec解析任务行 checkbox、正文、inline KV、emoji dates、tags。替代 parser.ts 中任务解析与字段特殊判断。
MarkdownBlockCodec解析 block KV、内容、边界注释、字段来源。替代 block parser 的 known key/unknown key 散落逻辑。
RecordNormalizer把 parsed record 归一为 NormalizedRecord，计算派生字段。替代 DataStore 中分散的 themePath、category、date 补齐。
FieldOriginCollector集中记录字段来源。替代无来源的 extra 和派生字段。
FieldValueResolver视图/筛选/搜索读取字段的唯一入口。替代 readField 里不断增加的特殊 if/else。
FieldValueCodec字段值读写 Markdown。替代 InputService/OutputPlanner/editStateResolver 对字段名的猜测。

禁止规则

禁止项原因替代方式
在任何地方写 item.theme || item.header。会重新污染主题。调用 getExplicitThemePath(item) 或 FieldValueResolver。
parser 自动生成 extra.正文 等 alias。会污染自定义字段。正文统一用 core editableText。
UI 通过字段 key 判断图片。图片能力无法复用。通过 field.type === image 判断。
筛选直接读取 item 原始属性。绕过字段语义、多值规则和来源。所有筛选走 FieldValueResolver。
legacy alias 写回新 Markdown。旧格式会永远续命。alias 只读，保存时写标准字段。
