全局数据筛选面板设计

本页记录 toolbar 数据筛选入口的产品形态、字段能力、交互边界和与旧主题/分类筛选的关系。

状态：MVP 已实施，宽面板、规则直接编辑与旧筛选迁移提示已纳入最后更新：2026-05-20格式：HTML关联计划：全局数据筛选与架构分层

设计目标

用户在 tp-toolbar 中不再只能筛选主题和分类，而是能打开一个“数据筛选”面板，对当前 layout 下所有视图统一生效。面板复用视图设置中已有的规则编辑能力，避免出现两套筛选模型。

特殊视图中的用户预期

  • 普通视图会同时响应全局筛选、视图局部筛选和当前日期范围。
  • 任务执行视图响应全局筛选和视图局部筛选，但不会因为当前日期范围隐藏循环任务本体；只会把完成记录限制在当前周期。
  • 统计视图如果全局筛选中明确选择了类别，会把统计类别列表同步收窄，避免界面仍显示无关类别。

用户入口

快捷区主题、分类、标签、日期等快捷入口。把常用筛选转换成普通规则。快捷区不是另一套状态。

面板尺寸与字段浏览策略

  • toolbar 只保留一个轻量入口，不直接展开复杂规则。
  • 点击后打开宽 Dialog 面板，目标宽度约 1180px，高度随视窗限制，内容区独立滚动。
  • 字段选择使用搜索型 Autocomplete，而不是窄下拉，适配 FIELD_REGISTRY + 动态 extra.* 字段较多的场景。
  • 已有规则用表格式行编辑展示，字段、条件、值、且/或都可以直接修改，避免删除后重建。
  • 空值 / 非空操作符不显示值输入框，多值和区间操作符显示对应输入提示。

旧筛选关系

旧的主题筛选和分类筛选不再作为长期独立状态继续扩张。没有 globalFilters 的旧布局会通过适配层只读转换成普通规则；用户打开面板时看到旧版提示，可以一键“转为新版规则”。编辑、删除或清空规则时也会自动写入 globalFilters 并清空旧字段，避免新旧双写。

selectedThemes     -> { field: 'themePath', op: 'in', value: [...] }
selectedCategories -> { field: 'baseCategory', op: 'in', value: [...] }
保存新版规则后     -> globalFilters + 清空 selectedThemes / selectedCategories

交互验收

  • 用户能看到当前启用多少条全局筛选规则。
  • 用户能新增、修改、删除、清空筛选规则；旧主题/分类筛选能显式迁移成新版规则。
  • 字段选择项使用中文 label 展示，但保存原始 key。
  • 清空全局筛选后，数据恢复到只受视图局部筛选和日期范围影响的状态。
  • 筛选结果为空时，视图应显示空状态，而不是报错。
