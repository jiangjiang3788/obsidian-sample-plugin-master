THINK OS PRODUCT DESIGN

目标闭环 MVP 方案

定义第一版只做什么：让一个真实目标能从创建、计划、任务、执行记录走到总结复盘和下一步调整。

状态：重定位草案 最后更新：2026-05-13 格式：HTML

MVP 目标

第一版不追求完整个人管理系统，只验证一条纵向闭环是否成立：用户创建一个目标，给它安排一个周期计划，拆成任务，执行时留下记录，周期结束做复盘，再看到能支持下一步调整的反馈。

完成标准：一个目标不再靠手工拼接计划 Block、任务、总结 Block 和 Statistics，而是能在系统里被连续追踪。

最小用户流程

  1. 创建目标：填写名称、周期、主题、衡量方式和当前状态。
  2. 制定周期计划：选择目标，创建本周期计划，写下承诺和优先级。
  3. 生成或关联任务：从计划拆出任务，或把已有任务挂回目标和周期。
  4. 执行任务：开始/完成任务，记录时间、状态、阻塞和产出。
  5. 补充执行记录：通过 QuickInput 或任务入口补记过程信息。
  6. 周期总结：查看本周期任务和记录，写下完成情况、偏差原因、有效行动和下周期调整。
  7. 查看反馈：看到目标维度的完成率、投入时间、偏差类型和下一周期建议。

MVP 范围

模块必须做暂不做
目标创建、查看、更新状态、关联周期。复杂层级目标、团队目标、权限。
周期计划为目标创建一个当前周期计划。自动排期、甘特图、多周期高级规划。
任务任务能关联目标、周期和计划。完整项目管理看板、复杂依赖。
执行记录记录时间、状态、阻塞、产出。全自动行为追踪。
总结复盘读取任务和记录，形成周期复盘。复杂复盘模板市场。
统计反馈按目标和周期展示基础反馈。多维报表、复杂图表系统。
AI仅保留后续入口，不作为 MVP 必需条件。自动生成完整目标管理方案。

页面与入口草案

入口用途第一版形态
目标列表查看所有进行中目标。按状态、主题、周期展示目标卡片或列表。
目标详情围绕单个目标查看计划、任务、记录、复盘和反馈。一页纵向闭环视图。
周期计划入口为目标制定本周期计划。表单或计划 Block 写入入口。
任务入口执行和更新任务。保留现有任务能力，补目标/周期上下文。
复盘入口关闭周期并写总结。总结 Block 升级为 Review 角色。
反馈入口解释推进情况。Statistics View 接入目标和周期过滤。

验收清单

  • 能创建一个目标，并为它设置当前周期。
  • 能为目标创建周期计划，并从计划生成或关联任务。
  • 任务执行后能留下至少一条执行记录。
  • 周期复盘能看到该目标下的任务和记录。
  • 统计反馈能按目标和周期解释推进情况。
  • 用户能根据复盘和反馈写出下一周期调整。
  • 旧 QuickInput 和 Statistics 不再作为主线入口，但可以作为输入和反馈支撑。
