字段配置与来源可解释交互设计

本页描述用户如何配置字段、理解字段来源、使用字段筛选。重点是把“字段类型”和“字段语义”从 UI 上分开，让 extra、themePath、header 不再混淆。

状态：当前有效最后更新：2026-05-21格式：HTML

用户目标

用户不需要理解内部字段债，只需要能完成三件事：创建字段时知道自己在选“字段类型”和“字段语义”；查看记录时知道字段值从哪里来；配置筛选时知道筛的是 themePath、tags、extra 还是文件字段。

字段配置 UI

区域内容要求
基础信息字段 label、key、描述。key 可自由命名；label 仅用于显示。
字段类型text、textarea、singleSelect、multiSelect、path、multiTag、image 等。类型决定输入控件和值结构。
字段语义title、body、themePath、categoryPath、tags、status、image 等。语义可为空；不靠 key 猜。
存储策略core、semantic、extra、file、derived、legacy。derived/file 默认只读；legacy 默认隐藏。
筛选搜索是否可筛选、操作符、是否进入全文搜索。图片默认不进入全文，只按资源名/alt 可选搜索。

字段来源解释 UI

展示位置内容
记录详情字段旁显示来源徽标：显式 / 派生 / 文件 / 历史。
字段 hover/popover展示 rawKey、sourcePath、sourceLine、origin、derivedFrom。
字段设置页列出该字段最近来源样本，帮助发现 legacy 或 extra 污染。
调试导出导出单条记录的 FieldOrigin JSON。

筛选面板文案修正

旧文案新文案原因
主题主题路径避免误以为是设置里的主题、heading 或旧 theme 字段。
标题记录标题 / 所在标题区分 title 和 header。
extra自定义字段extra 是存储分类，不应该直接暴露成用户概念。
文件名 / 文件路径文件字段明确它们来自文件，不是记录输入。

字段选择器分组

核心字段
  - 标题 title
  - 正文 editableText / content
  - 状态 status

语义字段
  - 主题路径 themePath
  - 分类路径 categoryPath
  - 标签 tags
  - 图片 image

文件字段
  - 所在标题 header
  - 文件名 file.name
  - 文件路径 file.path
  - 文件夹 folder

派生字段
  - 根主题 rootTheme
  - 末级主题 leafTheme
  - 日期时间戳 dateMs

自定义字段
  - extra.地点
  - extra.项目

历史兼容字段（默认隐藏）
  - theme
  - pintu
  - extra.正文 / extra.内容
