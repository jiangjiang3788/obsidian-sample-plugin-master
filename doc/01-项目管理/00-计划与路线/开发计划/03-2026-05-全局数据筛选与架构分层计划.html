2026-05 全局数据筛选与架构分层计划

本计划从 tp-toolbar 全字段筛选需求切入，把已有视图筛选能力收束为 Layout 级全局筛选、ViewInstance 局部筛选和统一数据筛选管线。

状态：代码完成，待依赖完整环境复验最后更新：2026-05-20格式：HTML生命周期：短期实施优先级：P0

本轮目标

把 toolbar 中写死的主题筛选和分类筛选，升级为一个可处理所有字段的数据筛选面板；同时把筛选状态、筛选规则、筛选执行和视图展示的职责分层，避免以后每增加一个筛选条件都要修改多个视图。

最小 MVP 标准

  • toolbar 有一个“数据筛选”入口，点击后能配置 FilterRule[]。
  • 筛选字段来自 FIELD_REGISTRY 和动态 extra.* 字段，不只限主题和分类。
  • 规则保存到当前 layout 的 globalFilters，刷新后仍然存在。
  • useViewData 同时应用 layout 全局筛选和 viewInstance 局部筛选。
  • 旧的主题/分类筛选数据不丢；未显式迁移前通过适配层继续生效，迁移后写入 globalFilters 并清空旧字段。

不在 MVP 中做

  • 不从数据模型中一次性删除 selectedThemes 和 selectedCategories，但 toolbar 不再把它们作为新的交互入口。
  • 不一次性清理所有 shared view container 的重复逻辑。
  • 不把 RuleBuilder 做成复杂查询语言；先保持现有规则模型可理解。
  • 不把筛选面板做成每个视图自己的设置入口；本轮只做 Layout 全局入口。
