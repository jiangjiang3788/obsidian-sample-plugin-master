目标闭环开发拆解

把目标闭环重构拆成可执行开发批次，明确每批计划时间、输入、输出、完成标准和不做事项。

状态：重定位草案 最后更新：2026-05-13 格式：HTML

开发策略

目标闭环重构不要从大规模目录整理开始，而要从一条可运行的纵向切片开始。先让一个目标能串起计划、任务、记录、复盘和反馈，再决定哪些目录和旧模块需要调整。

关键顺序：模型文档 → MVP 方案 → 技术关系模型 → 垂直切片实现 → Statistics 接入。

批次时间状态输入输出完成标准

第一刀开发范围

要做说明
目标最小模型能创建、读取、更新状态，能关联当前周期。
周期计划最小模型能为目标创建本周期计划，保留 Markdown 可读性。
任务上下文任务能带 goalId、cycleId、planId 中的关键关系。
执行记录Timer 或 QuickInput 产生的记录能挂到任务或目标。
复盘入口总结 Block 能读取本周期任务和记录。
基础反馈展示完成数、投入时间、阻塞数、复盘结论和下一步调整。

暂不做

  • 不先做大规模目录重构。
  • 不一次性替换所有旧字段和旧 Block。
  • 不做团队协作、权限、审批、复杂看板。
  • 不把 AI 放进 MVP 必需路径。
  • 不让 Statistics 先行定义数据模型。
