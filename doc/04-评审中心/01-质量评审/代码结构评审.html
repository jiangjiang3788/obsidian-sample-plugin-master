结构评审清单

检查项通过标准
文件职责一个文件职责清楚，不混杂过多领域。
依赖方向features 可依赖 app/core/shared，core 不直接依赖 UI 和 Obsidian 细节。
main.ts只做生命周期、命令和组合，不堆业务。
settings设置 UI、数据保存和业务逻辑不要互相缠绕。
platformObsidian API 调用有集中封装。
shared只放真正共享的东西，不做功能垃圾桶。
gate改动没有破坏架构检查。

必须追问

  • 这段代码三个月后还能看懂吗？
  • 换一个功能复用时会不会复制粘贴？
  • 它是不是放错层了？
  • 如果出 bug，第一时间能定位到哪个文件吗？
