全局数据筛选架构评审

本页用于实施前后评审全局数据筛选方案，重点检查状态真源、重复筛选、向后兼容、shared/ui 边界和测试覆盖。

状态：代码完成，待本地复验评审，legacy 迁移风险已收口最后更新：2026-05-20格式：HTML关联计划：全局数据筛选与架构分层

评审结论口径

通过标准不是“功能跑起来”，而是全局筛选成为一个可复用的数据能力：状态有唯一真源，筛选有统一管线，UI 只负责编辑规则，各视图不再各自扩展筛选分支。

风险清单

风险级别触发信号缓解方式验收检查
新旧筛选状态并存导致结果不可解释高同一 layout 同时写 selectedThemes 和 globalFilters，但没有转换说明。保留旧字段只读兼容，新修改写入 canonical globalFilters；面板给出旧版提示和显式迁移动作。刷新后筛选结果一致；清空新筛选不会回退旧字段；迁移后旧字段为空。
特殊视图重复筛选高TaskExecution 或 Timeline 自己再处理 theme/category/filter。普通视图通用过滤前移到 pipeline；TaskExecution 只复用 base filters；Timeline 不重复 filterByRules；Statistics 的类别收窄由 layoutFilters 派生。普通视图规则结果一致；TaskExecution 的 open task 不被日期范围误删，completed records 仍按 doneDate 落入本期；专项单测覆盖。
shared/ui 反向依赖业务状态中ViewToolbar 直接 import DataStore/useCases。DataFilterPanel 放在 feature 层，toolbar 只接收 slot 或抽象 props。shared/ui 不新增 app/features 内部依赖。

动态字段值输入体验差低extra 字段无法选值或类型错误。MVP 先支持手填；Phase 2 再加值建议和字段类型控件。extra 字段至少能保存、过滤、恢复。

实施前检查

  • 已确认 实施计划 中的 MVP 范围。
  • 已确认 功能设计 中字段范围和入口。
  • 已确认 技术管线 中状态真源和执行顺序。
  • 已决定本轮不删除 legacy 主题/分类字段。

实施后检查

检查项通过标准失败处理
功能toolbar 可配置任意字段规则并影响当前 layout。回退到旧 ThemeFilter/CategoryFilter，保留新模型代码待修复。
持久化刷新后 globalFilters 保留，不污染其他 layout。暂停扩展操作符，先修持久化。
兼容旧 layout 的主题和分类筛选仍生效，并可显式迁移为 globalFilters。补 legacy adapter 或迁移提示。
架构筛选执行集中在 pipeline，viewModel 不再扩张通用筛选。把重复筛选标记为 Phase 3 技术债。
验证相关单测、typecheck:src、verify:fast 通过。不得进入 Phase 2。

最终验收口径

本轮完成后，新增筛选字段时只需要在字段注册表或字段读取逻辑中补能力，不应该再改 toolbar、每个视图容器和每个 viewModel。若新增一个字段仍然要跨 3 个以上 UI/VM 文件手改，说明本轮分层没有完成。

最终验收结论

代码链路已经按计划完成：全局筛选真源、筛选管线、toolbar 面板、legacy 迁移、特殊视图收口和测试文件均已落地。当前仅缺依赖完整环境下的自动验证通过记录。

复验要求：先执行 npm ci，再执行 npm run typecheck:src、专项单测、npm run verify:fast 和 npm run docs:index。
