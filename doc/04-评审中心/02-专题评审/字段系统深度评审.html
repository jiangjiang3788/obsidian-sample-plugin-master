字段系统深度评审

评审对象

字段系统的完整方案正文已经迁移到 技术文档 / 字段系统重构方案。本页不重复技术正文，而是作为评审入口，用来判断方案是否适合进入实施。

评审维度

维度要判断的问题通过标准
架构边界字段内核、字段运行时、字段渲染协议是否分清？字段规则不再散落在 UI、表单、筛选、写回各处。
领域模型Task / Block / 模板 / 字段 / 能力开关是否边界清楚？字段不是单纯 UI 配置，而是可被输入、展示、筛选、写回复用的领域对象。
迁移风险是否能保留现有数据资产并逐步迁移？不能要求一次性推翻旧链路；必须允许 P0/P1/P2 分阶段推进。
实现顺序先做什么、后做什么是否明确？先统一核心字段和上下文，再收口 UI 与写回。
验收标准如何判断字段系统变稳定？新增字段不会牵一发动全身，字段显示、输入、筛选、写回语义一致。

评审结论模板

建议结论：字段系统值得作为一级架构对象重构，但应分阶段推进：先收口核心字段和上下文，再沉淀运行时协议，最后迁移 UI 和筛选/写回链路。
  • 通过：核心字段契约清楚，且有分阶段迁移方案。
  • 暂缓：如果只是改字段 UI，没有统一数据与语义协议。
  • 驳回：如果方案要求全仓重写、没有兼容旧数据路径。
