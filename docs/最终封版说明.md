# 最终封版说明

MVP25 是本轮“单人版破坏性收敛”的封版。封版目标不是继续拆更多文件，而是把已经完成的运行时收敛、视图抽离、非 shared view 收口和文档治理固化为可重复验证的维护边界。

## 封版结论

- 代码层：ThemeMatrix、ThemeOverride、legacy block/template/source 等旧兼容路径已经退出运行时主链路。
- 输入层：QuickInput、RecordInputFacade、AI 批量确认已经统一提交前归一化与批量结果汇总。
- 视图层：主要 shared view 已经完成模型层/展示层拆分，并由 shared view gate 防止大文件和 helper 回流。
- 非 shared view：RuleBuilder 已经抽出模型层，并由 non-shared view gate 固化；小型组件不再强拆。
- 文档层：docs 根目录已删除旧过程报告，只保留当前入口、验收、中文收敛记录、Git 备注和治理说明。

## 最终质量入口

### 完整本地验证

本地完整验证建议按以下顺序执行：

```bash
npm ci
npm run single-user:gate
npm run shared-view-convergence:gate
npm run non-shared-view-convergence:gate
npm run docs-governance:gate
npm run final-convergence:gate
npm run gate
npm run typecheck:src
npm run test:unit
npm run build
npm run build:release
npm run bundle:gate
```

其中 `npm run gate` 已经包含最终封版门禁和类型治理预算门禁；MVP27-MVP29 已连续下调 any 预算。

## 不再强拆的边界

以下组件保持现状，不再为了形式统一继续拆 `Model.ts`：

- `TimerView.tsx`
- `TimerViewView.tsx`
- `CategoryFilter.tsx`
- `ThemeFilter.tsx`
- `DayStatisticsView.tsx`
- `WeekStatisticsView.tsx`
- `FloatingPanel` 这类底层交互 primitive
- `ThemeTreeSelectPanel` 这类已经职责清楚的组合面板
- `NamePromptModal` 这类体量可控的简单 modal

后续只有满足以下条件之一，才继续抽离：

1. 主文件再次明显膨胀。
2. 出现可测试的非 UI 派生逻辑。
3. 出现跨视图重复规则。
4. 出现大段本地 helper 回流。

## 文档维护规则

- 新功能只写当前需要维护的说明，不再写长篇过程报告。
- 每轮变更若需要追踪，优先写中文收敛记录与 Git 备注。
- 旧过程类文件如 `GOAL_CENTER_*`、`GOAL_CORE_*`、`DATA_REVIEW_*`、`*_PASS_CHANGES` 不回流到 `docs/` 根目录。
- 中文文件名必须保持真实中文，不允许退回 `#Uxxxx` 编码形式。

## 交付建议

单人自用场景下，后续日常维护可以采用这个顺序：

1. 改代码或文档。
2. 跑对应专项 gate。
3. 跑 `npm run gate`。
4. 本地安装依赖后再跑 typecheck、unit test、build、release build。
5. 只在确实删除文件或准备完整覆盖时交付完整项目包；普通修改继续交付带路径的完整文件补丁包。
