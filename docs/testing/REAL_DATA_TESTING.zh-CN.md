# Think OS 真机测试：真实数据使用说明

## 可以使用真实数据吗？

可以。Think OS 是个人插件时，真实数据很有测试价值，因为它能暴露固定样本没有覆盖到的 Goal、Template、设置组合与历史配置兼容问题。

但要区分两件事：

1. **可以用真实数据的副本做测试。**
2. **不要让自动化测试直接修改正在使用的原始 Vault / 原始 data.json。**

当前 WDIO 真机测试使用 `test/vaults/simple` 作为测试 Vault，并通过测试启动器创建独立 Obsidian 沙盒。插件目录中的 `data.json` 会随插件副本进入沙盒，因此可以验证你当前真实 Goal / GoalTemplate / 设置的兼容性，但测试操作发生在沙盒副本中。

## Think OS 的约束

- 真机自动化创建的 Goal / Template / Record 尽量使用 `E2E` 命名空间。
- 清理逻辑只清理测试命名空间和测试 Vault 中的测试文件。
- 不允许把真实日常 Vault 路径直接配置成破坏性 E2E 的 `vault`。
- 如果以后需要测试真实 Markdown 数据，应先复制成临时快照，再让 WDIO 使用快照。
- 真机原始技术日志可能包含 Goal 路径、模板路径等真实配置；不要把完整日志公开发布。

## 为什么保留真实设置更适合你

对单人插件来说，固定空白配置只能证明“标准样本能运行”。真实设置副本还能证明：

- 多层 Goal 仍能加载；
- 大量 GoalTemplate 不会让插件初始化失败；
- 旧设置字段仍能被当前版本读取；
- 真实命令注册、Timer、AI、Quick Input 在你的配置规模下仍可启动。

因此本项目采用：**固定测试 Vault + 真实设置副本 + E2E 专用测试命名空间**。
