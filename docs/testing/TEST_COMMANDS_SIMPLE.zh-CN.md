# Think OS 测试命令：小白使用版

从 v9.5 开始，日常不再要求记几十条测试命令。

## 只记 4 条

### 1. `npm run 测试`

日常默认测试。直接运行单元测试 + 组合测试。

适合：每次改完代码先跑。

### 2. `npm run 测试:完整`

本机完整质量检查，包括：

- 功能测试地图严格审计
- 测试源码语法
- 工程质量
- 单元 + 组合测试
- 覆盖率
- 性能基线
- 故障实验室
- 质量报告

适合：准备提交代码、合并代码前。

### 3. `npm run 测试:真机`

构建当前源码并启动真实 Obsidian 测试用户流程。

适合：修改 UI、Quick Input、Timer、设置、Layout、AI Chat 等真实交互功能后。

### 4. `npm run 测试:发布`

发布前最终检查。在“完整检查”基础上继续运行：

- P0/P1/P2 真 Obsidian 测试
- 大 Vault
- Obsidian 兼容矩阵
- 不稳定测试重复运行
- 严格质量报告
- Release 构建

只有准备真正发布新版本时才需要运行。

## 出问题时才用的细分命令

| 命令 | 用途 |
|---|---|
| `npm run 测试:单元` | 只检查小功能/规则 |
| `npm run 测试:组合` | 只检查模块连接 |
| `npm run 测试:覆盖率` | 查看覆盖率 |
| `npm run 测试:性能` | 检查性能退化 |
| `npm run 测试:故障` | 主动制造坏文件、冲突、AI 失败等异常 |
| `npm run 测试:体系` | 查看功能测试地图 |
| `npm run 测试:语法` | 检查测试源码是否能解析 |
| `npm run 测试:帮助` | 在终端重新显示本说明的简版 |

## Windows 修正

单元、组合、覆盖率、性能测试现在直接调用：

```text
node ./node_modules/jest/bin/jest.js ... --runInBand
```

不再经过此前的 `run-jest-zh.mjs -> child_process -> Jest` 链路。

这条直连方式已经在 Windows PowerShell 上实际证明能够发现并执行 138 个单元测试文件。

`run-jest-zh.mjs` 暂时保留给历史脚本兼容，但不再是日常测试入口。
