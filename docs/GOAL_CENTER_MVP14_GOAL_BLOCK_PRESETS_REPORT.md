# Goal Center MVP14：目标 × Block 预设简化重构报告

## 这版解决的问题

这次重构针对四个明确反馈：

1. **导入已有目标需要折叠**：导入是迁移入口，不应该长期占据目标中心第一屏。
2. **新建目标不需要默认主题**：目标只描述“我要追踪什么”，主题不应成为目标创建的必填或默认绑定项。
3. **目标需要删除功能**：归档不是删除。目标库需要明确的删除动作，并清理该目标下的周期、关系和预设。
4. **预设不应成为新界面/新实体感**：用户需要的是“每个目标下，每个 Block 可以有多个预设”，不是再管理一个独立的“预设系统”。

本版的核心判断是：

```text
目标 × Block = 预设容器
一个目标下的每个 Block，可以直接创建多个预设。
```

也就是说，预设不再被包装成额外的一层产品对象。它只是某个目标下某个 Block 的多种写法。

---

## 设计原则

### 1. 如非必要，勿增实体

保留底层 `GoalTemplate / variantId`，但不在界面里把它当成独立实体展示。

用户看到的是：

```text
#照顾好自己 × 打卡
- 运动打卡
- 饮水打卡
- 睡眠打卡
```

而不是：

```text
目标模板
模板变体
variantId
模板矩阵
```

### 2. 目标只管“追踪对象”

目标中心里的目标只回答：

```text
我正在追踪什么？
```

所以新建目标表单删除了“默认主题路径”。主题属于分类、视觉或领域元数据，不应该阻碍目标创建。

### 3. 周期不是绑定实体

目标不再被解释成“必须绑定周期”。

周期只作为统计/表单默认窗口：

```text
不选择 = 日
可选 = 周 / 月 / 季 / 年
```

底层也把默认值从 `week` 改成了 `day`，包括新建目标、旧目标导入、派生周期和快速输入上下文。

### 4. 预设直接挂在目标 × Block 下

上一版的问题是增加了“记录预设”管理页，用户会问：

```text
我新增的预设去哪了？
```

这版改成：

```text
先选目标
下面直接列出所有 Block
每个 Block 卡片里直接添加、编辑、复制、删除多个预设
```

新增后预设会马上出现在对应的目标 × Block 卡片里。

## 用户界面变化

### 目标页

目标页现在包含三块：

```text
从已有记录导入目标  折叠
新建目标
目标库
```

#### 从已有记录导入目标

改为折叠区：

```text
从已有记录导入目标 · 10 个可导入
```

展开后才看到候选目标和“导入全部”。

#### 新建目标

旧表单：

```text
目标路径
默认主题路径
周期
新建目标
```

新表单：

```text
目标路径
周期（可选，默认日）
新建目标
```

其中周期选项只承担统计默认窗口，不创建周期实体。

#### 目标库

每个目标行新增：

```text
暂停
完成
归档
删除
```

删除目标会调用 `useCases.goal.deleteGoal(goal.id)`，清理：

```text
目标实体
目标周期
目标记录关系
该目标下的所有 GoalTemplate / 预设
```

不会删除已有 Markdown 文件。

## 目标 × Block 页

顶部只做目标选择：

```text
当前目标：#照顾好自己
```

下面按 Block 展开：

```text
#照顾好自己 × 打卡
  运动打卡
  饮水打卡
  睡眠打卡
  [添加预设]

#照顾好自己 × 任务
  普通任务
  习惯任务
  [添加预设]
```

每个 Block 卡片内支持：

```text
添加预设
编辑
复制
设默认
上移
下移
删除
```

新增预设不是跳到另一个“新增预设界面”，而是在当前 Block 卡片里直接展开一个内联编辑区。

## 数据模型边界

### 用户心智模型

```text
目标 = 我要追踪什么
Block = 我要记录哪类事
预设 = 这个目标下，这个 Block 的一种具体写法
```

### 底层模型

仍然沿用：

```text
GoalTemplate(goalId, coreBlockId, variantId)
```

但 UI 不再强调 `GoalTemplate` 或 `variantId`。

### 映射关系

```text
目标 × Block
  -> 多个 GoalTemplate variants
  -> UI 显示为多个预设
```

这样既保留多模板能力，也避免把工程模型暴露给用户。

## 关键代码改动

### 1. `GoalEntitySection.tsx`

改动：

- 导入已有目标改为 `<details>` 折叠区。
- 新建目标删除“默认主题路径”。
- 新建目标周期默认空选择，保存时空值写入 `day`。
- 目标库新增“删除”按钮。
- 目标行内显示“统计周期：日/周/月/季/年”。

### 2. `GoalTemplateSection.tsx`

重写为目标 × Block 直接结构：

- 先选择一个目标。
- 每个 Block 一个卡片。
- 卡片里直接列出该目标下该 Block 的所有预设。
- 添加/编辑预设在卡片内展开，不再作为独立页面感知。
- 保存后消息明确显示保存位置：

```text
已保存到「目标 × Block」
```

### 3. `GoalManager.tsx`

一级入口从“记录预设”改成：

```text
目标 × Block
```

减少“新增预设系统”的感觉，强化映射关系。

### 4. `goal.usecase.ts`

默认目标粒度从 `week` 改成 `day`：

```ts
granularity: input.granularity || 'day'
```

旧目标导入也默认 `day`，并且不再给导入目标绑定 `candidate.themePath`。

### 5. 派生周期默认值

这些地方的默认周期从 `week` 收敛为 `day`：

```text
src/core/goal/period.ts
src/core/goal/overview.ts
src/core/services/recordInput/snapshot/OutputPlanner.ts
src/app/ui/components/QuickInputEditor/QuickInputEditorContainer.tsx
src/features/settings/viewModels/goalDetailViewModel.ts
```

这样“不选择默认日”在数据层和 UI 层一致。

## 为什么这版更简洁

上一版的结构更像：

```text
目标中心
  目标
  记录预设
    选择目标
    选择 Block
    新增预设
    编辑预设
```

这版改成：

```text
目标中心
  目标
  目标 × Block
    #目标A × 打卡
      预设1
      预设2
    #目标A × 任务
      预设1
```

它减少了一个认知层级：用户不再问“预设在哪里”，因为预设就在目标和 Block 的交叉点下面。

## 结论

这版不是删除多模板变体，而是把多模板变体降回它应该处在的位置：

```text
目标 × Block 下的多个预设
```

目标中心不再像数据库后台，也不再把“预设”做成额外实体。用户的操作路径变成：

```text
选目标
找 Block
在这个 Block 下面添加多个预设
```

这是更符合直觉、也更符合“如非必要勿增实体”的版本。
