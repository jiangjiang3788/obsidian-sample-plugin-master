# 类型治理计划

MVP26 起，单人版收敛从“结构治理 / 视图治理 / 文档治理”进入“类型治理”。当前不追求一版清零 `any`，而是先建立预算、边界工具和验收方式，后续逐版下降。MVP27 已开始第一轮实际下降，优先处理 QuickInput 和 editState 核心输入链路；MVP28 继续清理 AI 动态输入边界和本地检索兜底边界；MVP29 继续清理目标预设模型、字段解析和筛选核心。

## 当前基线

MVP26 新增 `any-budget:gate` 后，当前显式 `any` 基线为：

| 范围 | MVP26 基线 | MVP27 计数 | MVP28 计数 | MVP29 当前计数 | MVP29 预算 |
|---|---:|---:|---:|---:|---:|
| `src` | 1087 | 1017 | 933 | 870 | 875 |
| `test` | 164 | 164 | 164 | 164 | 165 |
| `scripts` | 2 | 2 | 2 | 2 | 15 |
| 总计 | 1253 | 1183 | 1099 | 1036 | 1040 |
| `as any` | 583 | 578 | 556 | 516 | 520 |
| `: any` | 555 | 510 | 456 | 436 | 440 |

说明：这个基线来自门禁脚本去掉注释和字符串后的显式 `any` 统计，和普通 `rg any` 的结果不同。后续以 `npm run any-budget:gate` 为准。

## 治理原则

1. 边界可以保留少量 `any`，内部模型不应继续扩散 `any`。
2. 外部输入先进入 `unknown`，再用安全读取工具转成明确类型。
3. 不做全局机械替换，不把 `any` 简单改成大量 `as Foo`。
4. 先治理核心输入链路和模型层，再治理 UI primitive 和测试 mock。
5. 每一轮降低预算，不能让 `any` 数量反弹。

## 允许暂缓的边界

| 边界 | 处理策略 |
|---|---|
| Obsidian / DOM / 第三方 API | 用最小 port 类型逐步收窄，不强行一次性完美类型化 |
| AI 输出 / Markdown / JSON / 旧设置 | 先用 `UnknownRecord` helper 解码，再进入内部模型 |
| 测试 mock | 后置处理，优先抽通用 mock helper |
| 一次性脚本 | 预算较宽，但不能失控增长 |

## 后续优先级

| 顺序 | 目标 | 原因 |
|---:|---|---|
| 1 | `src/core/goal/overview.ts` | 目标概览是业务核心，当前仍在 top files 中 |
| 2 | `recordCreateActions.ts` | 记录创建动作链路仍有显式 `any` |
| 3 | shared view model 扫尾 | `heatmapViewModel`、`TimelineViewModel`、`statisticsViewModel` 等模型层应继续收紧 |
| 4 | UI primitive / 测试 mock | 有收益但不作为第一优先级 |

## 最小 MVP 标准

MVP29 之后的最小标准是：

```bash
npm run any-budget:gate
npm run gate
```

必须通过；后续每一版都应降低 `src` 或总量预算，除非明确说明新增的边界类型债。
