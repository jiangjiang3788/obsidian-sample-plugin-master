# 单人版收敛总览

本项目现在按“单人自用插件”维护：不发布插件市场，不追求旧数据兼容，不保留双系统。收敛目标是让运行时路径更少、主文件更小、模型逻辑更可测试、文档入口更清楚。

## 当前主线

| 阶段 | 重点 | 结果 |
|---|---|---|
| MVP1-MVP3 | 删除 ThemeMatrix、ThemeOverride、legacy block/template/source 等旧系统 | 运行时路径从多套兼容逻辑收敛到当前目标/预设/核心 block 路径 |
| MVP4-MVP9 | QuickInput 与 GoalTemplate UI 拆模型/拆组件 | 主输入和目标预设管理主文件大幅瘦身 |
| MVP10-MVP11 | RecordInputFacade 与 AI 批量确认模型化 | QuickInput 与 AI 批量确认复用同一提交前归一化/批量结果汇总逻辑 |
| MVP12-MVP22 | shared view 逐个抽离并建立总门禁 | Heatmap、Progress、Timeline、Excel、Statistics、EventTimeline、TaskExecution、BlockView、TableView 等进入模型/子组件结构 |
| MVP23 | 非 shared view 大容器盘点 | RuleBuilder 抽模型，并建立 non-shared view 收敛门禁 |
| MVP24 | 文档治理 | 删除旧过程报告，保留中文收敛记录、Git 备注、验收文档和当前入口 |
| MVP25 | 最终封版 | 加入最终封版说明和 final-convergence gate，固化不再继续拆的维护边界 |
| MVP26 | 类型治理基础设施 | 加入 any-budget gate、UnknownRecord 安全读取工具和类型治理计划 |
| MVP27 | 类型治理第一刀 | QuickInputEditorModel 与 editStateResolver 显式 any 清零，并下调 any 预算 |
| MVP28 | AI 动态输入边界类型治理 | AI parser / AI batch confirm / RetrievalService 显式 any 清零 |
| MVP29 | 模板模型与字段筛选核心类型治理 | GoalTemplateEditorModel / itemFilter / FieldValueResolver 显式 any 清零 |

## 当前质量入口

```bash
npm run single-user:gate
npm run shared-view-convergence:gate
npm run non-shared-view-convergence:gate
npm run docs-governance:gate
npm run final-convergence:gate
npm run any-budget:gate
npm run gate
```

## 不再继续拆的边界

以下组件已经足够小或职责足够清楚，不再为了形式统一继续拆 `Model.ts`：

- `TimerView.tsx`
- `TimerViewView.tsx`
- `CategoryFilter.tsx`
- `ThemeFilter.tsx`
- `DayStatisticsView.tsx`
- `WeekStatisticsView.tsx`

后续只有在出现明确计算、重复规则、状态派生或测试价值时才继续抽离。
