# Think OS 1.18.4：连续七天时间轴手势回退修正

## 用户真实需求（本次不能改变）

用户指出“看不到星期日”是因为横向滑动过快、抬手后继续甩动甚至发生整段跳转，**不是**因为星期日缺列或需要重排周视图。本轮**不实施**“七天总览 / 宽列详情 / 选一天切换模式”，保留原来的连续七列、统计栏、时间网格、时间块及三端交互入口。

## 证据与诊断判断

- 用户上传的 iPhone `schema: 2` 新日志共有 24 次触摸，包含约 `-105.7px` 的手指横移伴随时间轴 `-484px` 的一次性回跳（且仅 1 个滚动事件）。
- 其他手势抬手后仍产生数十到数百像素的横向追加位移。典型为 `-129px` 手指移动、最终 `+188px` 滚动，其中 `+60px` 发生在抬手后。
- 时间轴区域的多数横滑记录显示 **timeline-only**，并不能认定“多个页面同步横滑”。用户在其他模块进行纵滑时确实出现外层 `div` 的滚动，这是不同区域的正常滚动归属；不作为拆除 Dashboard 的理由。
- 1.18.3 源码的 `TimelineAxisPan.ts` 保留 `requestAnimationFrame` 横向惯性；手机 CSS 又将 `.timeline-view-wrapper` 设为 `overflow-x: hidden`；新触摸还能沿用尚未结束的纵向保护坐标。这些均可能导致用户感觉“失控/跳过星期日”。日志不能唯一证明某一条语句造成全部问题，因此以缩小控制权为修复目标。

## 最小完整方案

1. **恢复原来的 X 轴滚动容器 CSS**：撤销 1.18.3 额外添加的 `overflow-x: hidden`，保留 `.timeline-view-wrapper` 的 `overflow-x:auto; overflow-y:auto`、单滚动口和 `touch-action:pan-y`。
2. **取消额外 X 轴惯性**：手机横滑只跟随活跃手指，手指松开立即停止，不自动甩动、吸附或切换日期；每次触摸从当前实际 `scrollLeft` 开始，限制在 `0...maxScrollLeft`。
3. **Y 优先方向选择**：超过 16 px 才判定；横向位移需超过纵向 2 倍才认领 X。模糊斜滑归 Y；原生 Y 动画与惯性不受 JS 改写。
4. **Y 惯性保护但不污染下一次手势**：纵向期间只保持 X 不变；松开后的保护通过实际滚动静止结束；新手指落下立即清理旧保护，再读取实时坐标，不复用老 X。
5. **处理子事件后阻止宿主页面抢 X**：只在已确认 X 时，等时间块的子事件处理完后才在时间轴冒泡边界停止继续传播；Y、长按、双指及缩放不阻断。
6. **其他全部不变**：一周列数量、宽度、排序、时间轴块/摇杆、更新命令、内置诊断、持久化结构均不修改。
