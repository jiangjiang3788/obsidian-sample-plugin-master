# Goal Center MVP13：简约目标中心 + 多记录预设设计报告

## 1. 本次目标

本次不是继续增加配置项，而是做一次“减法重构”：

- 目标中心只管理“我要追踪什么”。
- Block 继续作为全局默认记录方式。
- 目标侧保留多模板变体能力，但不再暴露为“模板实体 / variantId / 排序数字 / 矩阵”。
- 多模板变体在用户界面中统一改名为“记录预设”。
- Goal x Block x Template 继续作为底层能力保留，但不作为用户的主认知模型。

核心判断：

> 多模板变体是必要能力，但不应该被包装成后台配置表单。它应该表现为用户能理解的“记录预设”。

---

## 2. 产品模型重新定义

### 2.1 用户可见模型

| 用户看到的概念 | 含义 |
| --- | --- |
| 目标 | 我要追踪什么，例如“照顾好自己”“产品化/目标中心” |
| 记录类型 | 我要记录哪类事情，例如任务、打卡、复盘，由 Block 提供 |
| 记录预设 | 同一目标 + 记录类型下的多种写法，例如运动打卡、饮水打卡、睡眠打卡 |
| 指标 | 目标的可追踪完成标准 |

### 2.2 用户不应该默认看到的概念

以下概念仍可存在于底层，但不应作为主界面术语：

- GoalTemplate
- GoalBlockBinding
- variantId
- sortOrder
- Goal x Block Matrix
- enabled / disabled 技术状态
- outputTemplate 大文本框

这些属于实现细节或高级配置。

## 3. 架构边界

### 3.1 Block 模板负责全局默认

Block 是固定动作类型，例如：

- 任务
- 打卡
- 计划
- 总结
- 阻碍项
- 里程碑

Block 模板继续负责：

- 默认字段
- 默认输出文件
- 默认标题位置
- 默认 Markdown 输出模板

### 3.2 目标记录预设只负责例外和多写法

目标侧只在需要时创建记录预设。

例如：

```text
目标：#照顾好自己
记录类型：打卡
记录预设：
- 运动打卡
- 饮水打卡
- 睡眠打卡
```

如果某个目标没有专属预设，就继续继承 Block 默认模板，不额外创建实体。

### 3.3 底层仍然复用 GoalTemplate

为了兼容现有数据，本次没有破坏底层结构：

```ts
type GoalTemplate = {
  goalId: string;
  coreBlockId: string;
  variantId?: string;
  name?: string;
  isDefault?: boolean;
  sortOrder?: number;
  enabled: boolean;
  targetFile?: string;
  appendUnderHeader?: string;
  outputTemplate?: string;
  defaultValues?: Record<string, unknown>;
  requiredFields?: string[];
};
```

UI 层把它解释为：

```text
GoalTemplate = 目标记录预设
variantId = 内部预设 ID
name = 预设名称
isDefault = 默认预设
enabled = 是否在快速输入显示
sortOrder = 预设顺序
```

## 4. 界面设计原则

本次参考 iOS 式信息组织，不追求表面拟态，而追求这四点：

1. 一个页面只服务一个主任务。
2. 默认界面不暴露数据库字段。
3. 高级能力渐进披露。
4. 用户先看到可执行动作，再看到配置细节。

### 4.1 目标中心首页

旧版用“四步卡片”强调配置流程。新版改为轻量 segmented control：

- 目标
- 记录预设
- 指标
- 高级

顶部只保留必要状态：

- 目标数量
- 可导入数量
- 预设数量
- 待整理数量

文案改为：

> 这里只管理“我要追踪什么”。记录方式默认继承 Block 模板；只有需要多种写法时，才为某个目标添加记录预设。

### 4.2 记录预设页

旧版问题：

- 一进来就是矩阵。
- 表单同时展示模板代号、名称、排序、默认、启用、保存文件、标题、输出模板、必填字段、默认值。
- 用户无法判断哪些是必须的。

新版改为三段：

1. 选择目标和记录类型。
2. 查看当前预设列表。
3. 编辑当前预设。

主编辑区只显示：

- 预设名称
- 说明
- 默认使用这个预设
- 在快速输入里显示
- 字段必填
- 字段默认值

高级输出设置折叠起来：

- 保存到文件
- 写入标题下
- 输出模板

这样既保留能力，又不会让普通用户先面对 Markdown 输出模板。

### 4.3 矩阵降级

Goal x Block 矩阵仍然保留，因为它对诊断有价值。

但它不再作为记录预设页的第一屏，而是放到页面底部的折叠区：

```text
高级诊断：目标 × 记录类型总览
```

用户不需要日常打开它。

## 5. 交互规则

### 5.1 继承规则

如果某个目标 + 记录类型没有记录预设：

```text
使用 Block 默认模板
```

不会创建额外数据。

### 5.2 多预设规则

如果有多个记录预设：

- 快速输入显示“记录预设”选择。
- 默认预设优先选中。
- 用户可以选择其他预设。

### 5.3 默认规则

同一个目标 + 记录类型下应只有一个默认预设。

保存一个预设为默认时，底层 `upsertGoalTemplateInSettings` 会把同组其他预设降级为非默认。

### 5.4 隐藏规则

旧 UI 使用“启用 / 禁用”。新版改为用户可理解的：

```text
在快速输入里显示
```

取消勾选后，底层仍保存为 `enabled: false`。

### 5.5 排序规则

用户不再看到排序数字。

只保留：

- 上移
- 下移

底层仍写入 `sortOrder`。

### 5.6 ID 规则

用户不再填写 `variantId`。

新建预设时根据名称生成稳定 ID：

```text
运动打卡 -> 运动打卡
Workout Check -> Workout-Check
```

旧预设继续保留原有 ID，不因为改名而破坏历史引用。

## 7. 为什么这版更简约

### 7.1 没有删除必要能力

多模板变体仍然存在：

```text
一个目标 + 一个记录类型 = 多个记录预设
```

### 7.2 删除的是错误层级

删除或隐藏的是：

- 矩阵作为主入口
- variantId 作为用户输入项
- sortOrder 数字输入
- 启用/禁用工程词
- 输出模板大文本框默认展示

### 7.3 保留的是用户任务

用户只需要回答：

1. 给哪个目标？
2. 给哪种记录类型？
3. 这个预设叫什么？
4. 哪些字段必填？
5. 哪些字段默认带出？
6. 是否作为默认？

这就是更接近 iOS 的“少选项、强默认、逐层展开”。

## 8. 使用示例

### 示例：给“照顾好自己”配置多个打卡预设

1. 进入 数据管理 → 目标中心 → 记录预设。
2. 目标选择：`#照顾好自己`。
3. 记录类型选择：`打卡`。
4. 新增预设：`运动打卡`。
5. 勾选必填字段：运动项目、时长。
6. 默认值可填写：主题 = `#照顾好自己`。
7. 保存。
8. 继续新增：`饮水打卡`、`睡眠打卡`。
9. 把最常用的设为默认。

快速输入时：

```text
目标：#照顾好自己
记录类型：打卡
记录预设：运动打卡 / 饮水打卡 / 睡眠打卡
```

## 9. 风险和后续建议

### 9.1 当前风险

- 旧数据里如果已经存在多个默认预设，需要通过高级诊断整理。
- `variantId = default` 在底层仍天然倾向于默认；为了兼容旧数据，本次没有改变该行为。
- 高级矩阵编辑器仍保留较多能力，但已从主流程移走。

### 9.2 后续建议

- 在目标详情页中增加“记录方式”摘要，显示每种记录类型有几个预设。
- 在 QuickInput 中记住用户上次选择的记录预设。
- 支持拖拽排序，替代“上移 / 下移”。
- 将高级矩阵移动到开发者模式或高级设置。
- 给记录预设增加图标字段，例如 🏃 运动、💧 饮水、🌙 睡眠。

---

## 10. 最终结论

本次设计没有否定多模板变体，而是重新命名和重新分层：

```text
目标 = 我要追踪什么
记录类型 = 我要记录哪类事情
记录预设 = 这类事情在这个目标下的几种常用写法
Block 模板 = 全局默认记录方式
GoalTemplate = 底层兼容存储，不作为用户主概念
```

这版的核心变化是：

> 保留复杂能力，隐藏工程复杂度；用户只看到“记录预设”。
