# GOAL_CENTER_MVP35_HEATMAP_GOAL_FIRST_FIX_REPORT

## 背景

用户发现打卡视图仍然像旧主题热力图：不同打卡图标直接混在月份格子里，看不出“这些打卡属于哪个目标”。

这不是打卡数据坏了，而是 Heatmap 仍沿用旧主轴：

```text
主题 → 日期格子
```

目标迁移后，正确主轴应是：

```text
目标 → 主题/打卡预设 → 日期格子
```

也就是说，主题不能再作为第一层展示主线；主题应该留在目标下面，表示这个目标下的不同打卡表单/主题维度。

## 本版目标

- Heatmap 按目标分组展示。
- 每个目标下面可以显示多个打卡主题/预设来源。
- 点击空白格新增时，同时带入目标和主题。
- 不再把所有打卡混成一张默认热力图。
- 保留主题作为二级维度，不重新把主题变成目标。

## 修改内容

### 1. Heatmap ViewModel 改成目标优先

文件：`src/features/settings/viewModels/heatmapViewModel.ts`

新增目标分组模型：

```text
GoalHeatmapGroup
  goalPath
  label
  count
  entries[]
    themePath
    label
    count
    dataForTheme
```

聚合逻辑改为：

```text
item.goalPath / 目标 / goalId
→ 目标分组
item.themePath / 主题
→ 目标下的二级打卡分组
item.date
→ 日期格子
```

### 2. Heatmap UI 改成目标分区

文件：`src/shared/ui/views/HeatmapView.tsx`

原来是：

```text
睡眠
运动
心情
姨妈
```

现在是：

```text
#照顾好自己
  睡眠
  心情
  姨妈

#强健身体
  运动
  身体
```

年/季/月/周/天视图都会先按目标分区。

### 3. 点击新增时带入目标

文件：

- `src/shared/types/actions.ts`
- `src/features/settings/layout/useViewRuntimeHandlers.ts`
- `src/app/actions/recordCreateActions.ts`

Heatmap 创建请求新增：

```text
goalPath
```

点击某个目标下的空白打卡格时，QuickInput 上下文会带入：

```text
目标:: 当前目标
主题:: 当前主题
日期:: 当前日期
```

这样新增记录不会只带主题而丢掉目标。

### 4. 保留上版主题读取修复

本版继续保留统一主题读取：

```text
item.themePath
item.themePathNormalized
item.theme
item.extra.themePath
item.extra["主题"]
```

避免旧记录迁移后主题字段位置变化导致落入 `__default__`。

## 来龙去脉

旧时代 Heatmap 是给主题用的，主题就是打卡对象，所以它直接显示：

```text
健康/运动
健康/睡眠
健康/心情
```

目标迁移以后，主题被降级成表单默认值和统计维度。真正的追踪对象变成目标：

```text
#照顾好自己
#强健身体
#身体健康
```

因此 Heatmap 也必须迁移：

```text
旧：主题 × 日期
新：目标 × 主题/预设 × 日期
```

这和目标模板矩阵是一致的：目标下面可以有多个表单，打卡视图里目标下面也应该可以有多个打卡。

## 验收方式

1. 打开打卡热力图。
2. 年/季/月/周视图应先看到目标分区。
3. 每个目标下面应显示多个打卡主题，比如睡眠、运动、早餐、晚餐。
4. 不同目标的同一天打卡不能混到同一个日历格子里。
5. 点击空白格新增记录时，QuickInput 应自动带入当前目标和主题。
6. 新建记录保存后，应能回到对应目标分区下显示。
