# 文档治理

MVP24 开始，`docs/` 根目录只承担轻量代码包文档职责，不再继续堆放每次探索、修复、迁移和过程型报告。

## 当前保留范围

`docs/` 根目录保留以下几类文件：

1. `README.md`：文档入口和阅读顺序。
2. `MVP_ACCEPTANCE.md`：最小发布验收清单，仍由 `mvp:gate` 检查。
3. `INITIAL_PLAN_PROGRESS.md`：原始工程计划进度摘要，仍保留给 `mvp:gate` 使用。
4. `单人版收敛总览.md`：MVP1-MVP30/MVP31/MVP32 的收敛主线索引。
5. `单人版收敛-MVP*.md`：单人版收敛过程记录。
6. `Git提交备注-MVP*.md`：每轮提交备注，便于复制到 Git commit message。
7. `文档治理.md`：本文档，说明保留/删除边界。
8. `类型治理计划.md`：MVP26 起的 any 预算、MVP27-MVP30/MVP31/MVP32 下降结果和动态输入边界治理计划。

## 防过度文档化规则

后续新增文档遵循以下规则：

- 有稳定入口价值才放在 `docs/` 根目录。
- 临时审计、一次性迁移说明、探索过程不要长期堆在根目录。
- 每轮 MVP 只保留一份中文收敛说明和一份 Git 提交备注。
- 代码行为以 gate 和测试为准，文档只记录入口、边界和决策。
- 如果文档无法指导验证、维护或提交，就不要新增。

## 门禁

MVP24 新增：

```bash
npm run docs-governance:gate
```

该门禁会检查：

- 必要文档入口是否存在。
- `docs/` 根目录是否重新出现旧过程报告。
- 是否出现 `#Uxxxx` 乱码文件名。
- `docs/` 根目录 markdown 数量是否重新膨胀。
- `docs/README.md` 是否说明文档治理和当前入口。

`docs-governance:gate` 已接入：

```bash
npm run gate
```


## MVP25 封版后的维护边界

MVP25 后，文档治理进入维护模式：

- 新增文档必须服务当前维护、验收、交付或排障，不再新增长篇过程报告。
- 如果只是记录一次普通代码修改，优先更新中文收敛记录和 Git 备注。
- 如果只是临时分析，不进入 `docs/` 根目录。
- `docs/最终封版说明.md` 是当前封版后的主要交付说明入口。
- `npm run final-convergence:gate` 会和 `docs-governance:gate` 一起防止最终文档入口缺失。
- `npm run any-budget:gate` 会阻止显式 any 数量在类型治理阶段继续反弹；MVP27 已将 src 预算从 1090 下调到 1020，MVP28 下调到 935，MVP29 下调到 875，MVP30/MVP31/MVP32 保持 870。
