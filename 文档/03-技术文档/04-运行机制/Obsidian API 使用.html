Obsidian API 使用

集中说明 Obsidian API 应该从哪里被调用，以及如何隔离宿主依赖。

状态：建议模板 最后更新：2026-05-07 格式：HTML

API 使用边界

项目已经存在 platform 和 core/ports。原则上，Obsidian API 调用应优先集中在 platform 实现里，core 通过 port 接口间接使用，避免核心逻辑直接绑定宿主环境。

Port 映射

Port平台实现用途
VaultPortObsidianVaultPort文件读取、写入、列表。
UiPortObsidianUiPort通知、UI 相关能力。
ModalPortObsidianModalPort弹窗相关能力。
EventsPortObsidianEventsPort事件订阅。
MetadataPortObsidianMetadataPort元数据读取。
FileStatPortObsidianFileStatPort文件状态信息。
MessageRenderPortObsidianMessageRenderPort消息/Markdown 渲染。

注意事项

  • 新增 Obsidian API 使用前，先判断是否应该新增 port。
  • 不要让 core 服务直接 import obsidian。
  • 命令和 UI 可以接近 Obsidian，但业务计算应下沉。
  • 涉及文件写入的 API 要考虑备份、失败和恢复。
