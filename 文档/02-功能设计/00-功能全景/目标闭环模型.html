THINK OS PRODUCT DESIGN

目标闭环模型

定义 Think OS 的产品主轴：目标、周期、计划、任务、执行记录、总结复盘、统计反馈如何组成一个可推进的闭环。

状态：重定位草案 最后更新：2026-05-13 格式：HTML

一句话模型

Think OS 不只是记录目标、计划、任务或统计，而是让用户能持续回答：我现在推进的目标是什么，本周期承诺了什么，今天做了什么，留下了什么证据，复盘后下一步要怎么调整。

主链路：目标 → 周期 → 计划 → 任务 → 执行记录 → 总结复盘 → 统计反馈 → 调整。

核心对象

对象定义必须回答的问题不是什么
Goal 目标用户想持续推进的结果或方向。我要推进什么？为什么重要？怎么算有进展？不是主题标签，也不是普通项目分类。
Cycle 周期目标推进的时间窗口，如周、月、阶段。这个周期要承诺什么？什么时候复盘？不是单个任务日期。
Plan 计划周期内对目标的行动安排。本周期准备怎么做？优先级是什么？不是一段孤立的计划文字。
Task 任务可以被执行和完成的行动单元。这件事服务哪个目标？来自哪个计划？不是无上下文待办。
Record 执行记录任务执行过程中留下的时间、状态、阻塞、产出等证据。实际做了什么？花了多久？结果如何？不是单纯日志堆积。
Review 总结复盘周期结束时对目标推进和偏差原因的解释。为什么完成/没完成？哪些动作有效？不是普通总结 Block。
Feedback 统计反馈从记录和复盘中聚合出的趋势、偏差和下一步提示。目标推进得怎么样？下一周期怎么调？不是孤立 Statistics 报表。

关系规则

关系规则设计含义
Goal - Cycle一个目标可以跨多个周期推进，一个周期可以承接多个目标。周期是目标推进的节奏，不是目标本身。
Cycle - Plan计划必须落在周期内，并能回到目标。计划 Block 要有上游目标和周期上下文。
Plan - Task任务可以来自计划，也可以后来补充，但必须能关联目标。临时任务也要能补齐上下文。
Task - Record执行记录优先挂到任务，没有任务时至少挂到目标或周期。QuickInput 和 Timer 都是记录入口。
Record - Review复盘需要读取任务和记录，解释计划与实际的偏差。总结不是孤立文字，而是闭环节点。
Review - Feedback统计反馈从任务、记录、复盘中抽取可解释信号。Statistics 要回答目标推进问题。

旧概念的新位置

旧概念新位置处理方式
主题 Theme分类维度主题可以辅助筛选目标和记录，但不等于目标。
Block记录形态计划 Block、总结 Block 需要有 recordRole 和上游关系。
View观察窗口视图服务闭环节点，不能反过来定义产品结构。
QuickInput输入通道负责快速创建任务、记录、复盘片段，但写入时要补上下文。
Statistics反馈解释器优先按目标和周期解释推进情况，再展示明细。
字段系统实现支撑字段要为目标闭环服务，旧字段需要逐步校准。

第一版边界

  • 先支持个人本地使用，不做团队协作、权限、审批。
  • 先支持一条目标闭环，不追求覆盖所有项目管理方法。
  • 先让计划、任务、记录、复盘能互相追溯，再做复杂统计。
  • 先保留旧 QuickInput、Statistics、字段系统作为实现参考，不在模型未定前大规模重构。
