推荐本地验证顺序

顺序命令目的失败时优先看
1npm ci安装 lockfile 固定依赖Node/npm 版本、网络、lockfile 冲突
2npm run gate确认分层、public API、DI、Obsidian API 边界新增 import 是否绕过 public/capability
2.5node --check main.js确认交付给 Obsidian 的插件入口 JS 可解析手工修补构建产物后的语法错误
3npm run typecheck:src确认生产代码类型正确core/public 新导出、目标闭环类型引用
4npm run test:unit -- recordUiActions只跑本轮新增的 UI action 回归测试QuickInputModal mock、@core/public mock、时间字段期望
5npm run test:unit -- recordInput.locator只跑本轮新增的 recordInput 定位 helper 回归测试路径解析、line number、候选记录评分
6npm run test:unit跑完整单元测试基线历史测试与新增类型/导出兼容性
7npm run build确认插件产物可构建Vite/Preact/MUI 构建链

进入路线图修改的最低门槛

  1. npm run gate 通过。
  2. npm run typecheck:src 通过。
  3. npm run test:unit -- recordUiActions 和 npm run test:unit -- recordInput.locator 通过。
  4. 手动在 Obsidian 中跑一次 QuickInput/RecordInput 创建记录链路，确认不会再出现 previewTemplateExecution undefined。
  5. 新增 Goal/Cycle/Record 功能只依赖 @core/public 暴露的契约，不直接 deep import core 内部文件。
  6. 新增 UI 入口不得直接 import Obsidian API；需要走 platform port 或 app public 能力。
